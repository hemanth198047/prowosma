# API Documentation

## Interactive reference

The full, always-current REST API reference is auto-generated by springdoc-openapi and served
directly by the running backend:

- Swagger UI: `{backend-url}/swagger-ui.html`
- Raw OpenAPI spec (JSON): `{backend-url}/v3/api-docs`

This was already working before this backlog — nothing needed fixing here. What was missing (and is
now addressed) is everything *around* it: versioning policy, breaking-change protection, and SDK
generation guidance.

## Versioning policy

This API does not currently use a versioned URL scheme (e.g. `/api/v2/...`) — see `docs/adr/` if a
future breaking change needs one; none has been necessary yet. Instead:

- **Backward-compatible changes** (new endpoints, new optional fields, new enum values) ship without
  ceremony.
- **Breaking changes** (removed endpoints, newly-required fields, removed enum values, changed field
  types) are caught automatically by `api-contract-check.yml` before merge — see
  `docs/API_CONTRACT.md`. If a breaking change is genuinely necessary, it should ship as a new endpoint
  path or a new required header/query param that opts into the new shape, keeping the old path
  functional for existing clients during a deprecation window.

## Deprecation policy

When an endpoint needs to be retired:
1. Mark it `@Deprecated` in code and note the deprecation + planned removal date in its Swagger
   `@Operation` description (visible directly in the interactive docs, not just source comments).
2. Keep it functional for at least one full release cycle after the deprecation is announced.
3. Log a warning (not an error) when a deprecated endpoint is hit, so real usage can be tracked before
   removal.

## SDK generation

No hand-maintained SDK exists, and none is committed to in this backlog — but one is straightforward to
generate on demand from the OpenAPI spec above using
[openapi-generator](https://openapi-generator.tech/), which supports dozens of target languages:

```bash
npx @openapitools/openapi-generator-cli generate \
  -i http://localhost:9090/v3/api-docs \
  -g typescript-fetch \
  -o ./generated-sdk
```

Not committed to a specific target language/publishing pipeline here since that depends on who the
external API consumers actually are (a decision, like several others in this backlog, that depends on
information only the product/business side has) — this is the concrete starting command once that's
decided.
